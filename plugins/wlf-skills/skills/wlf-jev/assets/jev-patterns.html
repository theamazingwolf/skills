Jev question patterns

Jev answers narrow questions about one piece of state with a typed answer and its probabilities. It has four question types. Pick the one whose answer shape your code needs.

Jev judges, code decides.Ask "does the customer sound frustrated?", then let code decide whether to escalate.
One request, many questions.Every question sees the same state and is answered independently, in parallel.
Confidence is not correctness.It measures how concentrated the answer is. Calibrate against human labels.
Failure is an error.A timeout is never "no". Choose what happens on failure, on purpose.

The four primitives

Noul: is this true?

noul

One statement, one probability of "yes". The number is both the answer and the uncertainty: near 0.5 means the state doesn't settle it.

Goes in

{
  type: "noul",
  instructions: "Does the customer in `message.body`
                 ask to speak with a person?",
  criteria: {            // optional
    false: "Only describes a problem; never asks
             for a person, a call or an agent."
  }
}

Comes out

{ type: "noul", noul: 0.82 }
// P(yes). No confidence field.
// Confidence-style proxy: |2p − 1| = 0.64
0 · no0.3review band0.7yes · 1
Pick it when
  • code branches on a yes/no
  • several labels can be true at once (one noul per label)
  • you need "is anything here?" next to a choice or box
Avoid
  • "and" / "or" inside one question: ask two
  • using 0.5 as "medium": that's a score
  • criteria where true describes a "no"

Choice: which one of these?

choice

A fixed set of named, unordered options. You get the top label and a probability for every option, summing to 1. The label is always one of yours, even when none fits.

Goes in

{
  type: "choice",
  instructions: "Which team should handle `doc.text`?",
  criteria: {
    finance:    "Payments, invoices, expenses, tax",
    legal:      "Contracts, disputes, compliance",
    people:     "Hiring, leave, benefits",
    operations: "Suppliers, deliveries, IT"
  }
}

Comes out

{
  type: "choice",
  choice: "legal",
  probabilities: { finance: 0.18, legal: 0.71,
                   people: 0.03, operations: 0.08 },
  confidence: 0.61   // (p_max − 1/n) / (1 − 1/n)
}

Other signals worth testing: the top probability itself, or the ratio of top to second (here 0.71 / 0.18 ≈ 3.9).

Pick it when
  • exactly one of a known set applies
  • you can describe each option in a line that separates it from its neighbours
  • up to 255 options; code removes ineligible ones first
Avoid
  • labels like A or option_1
  • a generic "always fits" option that crowds out real ones
  • "nothing fits" handling by assumption: an other option vs a companion noul is contested; test both

Score: which level?

score

An ordered rubric of 2–10 described levels, low to high. You get a probability per level, an expected score (Σ level × probability, so it can fall between levels) and a confidence.

Goes in

{
  type: "score",
  instructions: "How urgent is the situation
                 in `message.body`?",
  criteria: [
    "A question or suggestion; nothing blocked",
    "Inconvenient; a workaround exists",
    "Blocked for this customer, no workaround",
    "Money lost, data at risk, or many blocked"
  ]
}

Comes out

{
  type: "score",
  score: 2.12,          // expected level
  probabilities: { 0: 0.02, 1: 0.14,
                   2: 0.54, 3: 0.30 },
  legend: { 0: "A question…", … },
  confidence: 0.58
}

Pick it when
  • outcomes are ordered: severity, fit, quality, urgency
  • each level can be written as a concrete situation
  • a rubric: one score per criterion, combined in code
Avoid
  • adjectives ("moderately severe") or relative levels ("worse than the last")
  • two dimensions in one score
  • reading the fractional score as a measurement
Hiring rubric

One score per criterion, e.g. how much evidence application.experience shows of leading a team, from "none" to "led several teams for years".

Box: where in the image?

boxopt-in · not production-ready

Locates what the instructions describe in an image. Edges come back as fractions of height and width from the top-left. It always returns a box, even if the thing isn't there, so pair it with a presence noul.

Goes in

// header: TypeSafe-Danger-Zone-Images: true
// model: jev-1.14 only (as of 2026-11-02)
{
  state: image(bytes),   // PNG or JPEG
  questions: {
    has_logo: noul("Is a company logo visible?"),
    logo: { type: "box",
            instructions: "The company logo" }
  }
}

Comes out

{
  type: "box",
  box: { top: 0.12, bottom: 0.34,
         left: 0.58, right: 0.90 },
  confidence: 0.47   // may be null
}
// Ignore the box when has_logo is low.
Pick it when
  • prototyping "where is X in this image?"
  • you can pair it with a presence noul
Avoid
  • production use (vendor label, 2026-11-02)
  • images outside 280–1568 px per side or over 16 MiB: one bad image fails the request

Which primitive?

1
Is the answer a number, a count, a date comparison, a lookup or generated text?
yes → not Jev: do it in code (a choice may pick among candidates code found)no → continue
2
Is the input an image and the question "where"?
yes → box + a presence noulno → continue
3
Can more than one label be true at once?
yes → one noul per labelno → continue
4
Does code just branch on true / false?
yes → noulno → continue
5
Are the outcomes ordered, and can you describe each level as a situation?
yes → scoreno → continue
6
Is it one of a fixed set of unordered categories?
yes → choice (with a presence noul if "none" is possible)no → rethink the question: it may be a decision, not a judgment

Decomposing a request

The askBecomesCode does
"Should we escalate this ticket?"nouls: asks for a person? money being lost? · score: urgencya truth table → escalate or not
"Tag posts with any policy they break"one noul per policy clauseper-clause thresholds → flag list
"Grade this against our rubric"one score per criterion, one noul per pass/fail lineweights → total, plus a review band
"Is this agent command risky?"code facts first, then one noul per risklog / flag / block per check; a deliberate fail mode
"Route this document"choice over teams + "does any team fit?" noulroute, or send to a person when nothing fits

Before any threshold ships

A person labels 10–30 real examples for a first check (50–300 before trusting a production threshold). Run the questions, compare with the labels, read the most confident disagreements together, change one thing, and run again. Choose each check's threshold from its own accuracy-at-confidence table, keep a review band for unsure items, pin the model version, and re-run the suite whenever the model, the wording or the inputs change.

Everything placed in state is sent to TypeSafe. Keep secrets out.

Facts as of 2026-11-02. Model versions, limits and the opt-in features change; re-check the live documentation before relying on a number.
